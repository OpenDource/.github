
# Security Policy

Security is an important part of OpenDource.

We encourage responsible disclosure of security vulnerabilities in our projects.

## Reporting a Vulnerability

Please **do not publicly disclose security vulnerabilities through GitHub issues, discussions, or pull requests**.

Instead, report security issues privately through the security contact or reporting mechanism provided by the affected repository.

Include as much relevant information as possible, such as:

- A description of the vulnerability
- Affected repository and version
- Steps to reproduce
- Potential impact
- Proof of concept, when appropriate
- Suggested mitigation, if available

## What We Aim to Do

After receiving a valid security report, maintainers will:

1. Review the report.
2. Confirm and investigate the issue.
3. Assess its impact and severity.
4. Work on an appropriate fix.
5. Communicate relevant updates when possible.
6. Publish security information when appropriate.

Response and remediation timelines may vary depending on the severity and complexity of the issue.

## Responsible Disclosure

Please give maintainers reasonable time to investigate and address a vulnerability before publicly disclosing it.

We appreciate security researchers and contributors who help us improve the security of OpenDource projects.

## Supported Versions

Each repository may define its own supported versions.

Please refer to the repository's documentation and release information for version-specific support.

## Security Best Practices

Please do not commit:

- API keys
- Passwords
- Access tokens
- Private certificates
- Cloud credentials
- Environment secrets
- Personal or confidential information

Use environment variables or appropriate secret-management systems instead.

Thank you for helping keep OpenDource secure.
